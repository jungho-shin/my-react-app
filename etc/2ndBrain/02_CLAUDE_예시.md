```markdown
# 지식 위키 — 스키마 (CLAUDE.md)

이 볼트는 카파시의 "LLM Wiki" 패턴을 따른다.
raw(불변 원본) → wiki(내가 정제·유지) → 이 파일(규칙서)의 3레이어 구조.

## 3-레이어 구조
- `raw/`  : 원본 자료. 사용자만 추가한다. **Claude는 읽기 전용, 절대 수정/삭제 금지.**
- `wiki/` : 정리된 지식. **Claude가 작성·유지한다.** 사람은 읽기만.
  - `index.md` : 전체 목차 (카테고리별 링크 정리)
  - `log.md`   : 작업 이력 (append-only)
- `CLAUDE.md` : 이 파일. 규칙서.

## 3가지 운영 모드
### 1. 자료 넣기 (Ingest)
사용자가 raw/에 파일을 넣거나 "반영해줘"라고 하면:
1. 원본을 읽고, 어떤 위키 페이지에 영향을 주는지 판단
2. 새 지식이면 위키 페이지 생성, 기존 내용이면 해당 페이지 보강 (무조건 새 페이지 X)
3. 관련 페이지끼리 `[[위키링크]]`로 교차참조
4. `index.md` 갱신, `log.md`에 한 줄 기록

### 2. 질문하기 (Query)
사용자가 질문하면:
1. `index.md`를 먼저 훑어 관련 위키 페이지를 찾는다
2. 페이지들을 읽고 종합해 답한다. **반드시 근거를 `[[위키링크]]`로 인용**
3. 여러 페이지를 겹쳐야 보이는 연결/패턴을 적극적으로 제시
4. 답이 새로 가치 있으면 "이걸 위키에 저장할까요?" 물어본다

### 3. 건강검진 (Lint)
사용자가 "건강검진 해줘"라고 하면 위키 품질을 점검:
- 모순되는 서술 / 오래된 정보(특히 AI 도구)
- 깨진 링크(`[[존재하지-않는-페이지]]`)
- 고아 페이지(어디서도 링크 안 됨)
- 자주 언급되나 독립 페이지가 없는 주제 → 생성 제안
- 누락된 양방향 링크
→ 결과를 표로 보고하고, log.md에 기록, 발견된 문제는 (승인 후) 수정

## 위키 페이지 규칙
- 페이지 맨 앞에 `>` callout으로 **"핵심 한 줄"**(내 관점에서 가져갈 것)을 먼저 배치
- Frontmatter: `type / created / updated / tags`
- 파일명: 케밥케이스, 한글 허용 (예: `딥워크-깊은-집중.md`)
- 교차참조 적극 활용 — 관련 개념이 있으면 반드시 링크

## 작업 톤
- 교과서가 아니라 실무 노트로 쓴다. 무엇·왜에 집중, 군더더기 없이.
- 기존에 잘 되어 있는 페이지는 함부로 갈아엎지 않는다.
- "과거의 나 ↔ 현재의 나"의 차이는 모순이 아니라 '변화'로 기록한다.
```
